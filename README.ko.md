# Hermes Fit — Hermes Agent를 위한 근거 기반 개인화 도구

Hermes Fit은 **Hermes Agent의 반복 교정을 검토하는 오픈소스 스킬과 오프라인 Python 보조 도구**입니다. 사용자가 고른 대화에서 반복 수정 요청을 살펴보고, 작은 지침 변경을 제안하고, 별도 검수와 후속 피드백으로 확인하도록 돕습니다. 실제 변경은 사용자 승인과 Hermes 공식 도구를 거치며, 모델 자체를 자동 학습시키지는 않습니다.

**Hermes가 나를 배워야 하는데, 내가 Hermes를 배우고 있었다.**

같은 말을 반복하고 지침을 직접 관리하는 Hermes 사용자를 위해 근거 확인 → 변경 제안 → 승인 → 재검수 → 피드백 흐름을 제공합니다. 모든 불만을 새 전역 규칙으로 바꾸기보다 이미 잘되는 행동도 함께 살펴봅니다. Vision Kim과 Hermes Agent가 만든 커뮤니티 프로젝트이며 Nous Research나 Hermes 공식 제품이 아닙니다.

[공개 베타 0.1.0-beta.1](https://github.com/junghwoan/hermes-fit/releases/tag/v0.1.0-beta.1) · [English](README.md) · [피드백](https://github.com/junghwoan/hermes-fit/issues/1) · [자동시험](https://github.com/junghwoan/hermes-fit/actions/workflows/ci.yml)

## 합성 데이터로 먼저 체험하기

데모는 일회용 홈과 합성 데이터로 실행됩니다. 실제 대화를 읽거나 사용 중인 Hermes 프로필을 바꾸지 않습니다. Linux 또는 macOS에서 Git과 Python 3.10 이상이 필요하며 계정이나 API 키는 필요하지 않습니다.

```sh
git clone https://github.com/junghwoan/hermes-fit.git
cd hermes-fit
python3 --version
python3 examples/demo.py
```

또는 [배포 ZIP](https://github.com/junghwoan/hermes-fit/releases/tag/v0.1.0-beta.1)을 풀고 해당 폴더에서 Python 명령 두 줄을 실행하세요. 데모는 기록과 확인 절차를 보여주며, 실제 모델 실행이나 행동 개선 효과를 입증하는 시험은 아닙니다. `python3`가 3.10보다 낮으면 아래 명령에서도 모두 더 높은 버전의 Python을 사용하세요. 스킬 설치와 개인 대화 분석은 별도 단계입니다.

개인정보: 분석 대상으로 고른 대화는 선택한 모델 제공자에게 전달됩니다. 오프라인 도구가 가리기 전에 이미 전달됐을 수도 있습니다. 자동 가림은 모든 비밀을 찾지 못하므로 비밀 정보나 다른 사람의 대화를 선택하지 마세요. 이 도구 자체는 네트워크를 호출하지 않습니다.

## 채팅에서 사용하기

스킬이 설치된 호환 Hermes 대화에서 “선택한 대화의 반복 수정 요청을 살펴보고 근거가 있는 변경만 제안해 줘”라고 요청하세요. 프로필, 대화, 시간대가 포함된 기간, 작성자와 분석량을 지정합니다. 근거와 반대 근거를 확인한 뒤 변경마다 정확한 제안과 대상에 동의합니다. 실제 변경은 Hermes 공식 도구와 승인 절차를 따릅니다. 보조 도구는 공식 도구 호출을 계획하고 파일 상태를 확인하지만, 대화 상대의 신원이나 공식 도구 호출을 증명하지 못합니다. 스킬이나 USER 메모리 파일을 직접 고치지 않습니다.

의미 있는 변경 뒤에 한 번 “더 나은가요, 비슷한가요, 더 나빠졌나요?”라고 묻고 이유를 선택적으로 받을 수 있습니다. 답이 없으면 만족 여부는 알 수 없습니다. 좋은 점은 보존하고, 나쁜 평가는 원인 검토부터 합니다. 다음 수정에는 새 근거와 별도 재검토, 새 승인이 필요합니다. 한 문제의 수정은 기본 두 차례까지입니다. 이후 비슷한 작업의 결과는 관찰 기록이며 인과관계를 증명하지 않습니다.

## 로컬 시험과 설치

Linux 또는 macOS의 일회용 홈에서 시험하세요. 아래 명령은 임시 폴더 경로를 실제 경로로 바꿉니다.

```sh
FIT_HOME="$(python3 -c 'from pathlib import Path; from tempfile import mkdtemp; print(Path(mkdtemp(prefix="hermes-fit-")).resolve())')"
python3 packaging/install_local.py install --hermes-home "$FIT_HOME"
python3 -I "$FIT_HOME/skills/hermes-fit/scripts/hermes_fit.py" --help
python3 packaging/install_local.py uninstall --hermes-home "$FIT_HOME"
```

이미 설치된 대상이 있으면 덮어쓰지 않습니다. 제거할 때 설치 파일과 일치하는 Python 캐시만 지우고, 수정된 파일이나 알 수 없는 파일은 보존하고 알려줍니다. 일정이나 모니터가 남아 있으면 먼저 해제해야 합니다. 전체 시험은 `python3 -m unittest discover -s tests -v`로 실행합니다.

## 반복 점검

기본으로 생성되는 일정은 없습니다. 별도로 동의한 뒤 내보내기 파일, 프로필, 주기와 시간대를 고르고 실제 Hermes 버전과 현재 시간대를 확인하세요. v0.22.2의 정시 일정은 Hermes의 현재 시간대를 사용합니다. `every 24h` 같은 간격은 현지 시각이 아니라 경과 시간입니다. 선택한 내보내기 파일을 승인한 기간과 작성자 범위 안에서 직접 갱신해야 하며, 모든 새 대화를 자동으로 찾지는 않습니다.

Hermes에 `schedule-plan`을 요청하면 공식 도구의 목록 조회와 일시 정지된 로컬 일정 생성 계획을 받습니다. 공식 도구로 목록을 조회한 결과를 `schedule-setup`에 전달하고, 생성 계획을 공식 도구로 실행한 뒤 다시 목록을 조회합니다. `schedule-register`는 두 응답과 전체 내용을 담은 읽기 전용 `cron.jobs.get_job` 기록을 대조한 뒤 재개·일시 정지·제거 계획을 제공합니다. 목록의 미리보기만 확인한 상태에서는 재개하면 안 됩니다. 프로필·시간대·버전과 도구 응답은 호출자가 제공하므로 인증된 영수증은 아닙니다. 재개에는 별도 동의가 필요합니다. 일정 제거는 새 목록으로 `schedule-teardown-plan`을 만든 뒤 공식 도구로 제거하고, 제거 결과와 부재가 확인된 새 목록으로 `schedule-cleanup`을 실행합니다. 모니터가 수정됐거나 검토 대기 항목이 있으면 정리를 중단합니다. [상세 절차](skills/hermes-fit/references/workflow.md#optional-schedule)를 참고하세요.

모니터는 내용이 같으면 같은 출력을 내고, 제안이 검토 대기 중이면 이전 출력을 유지합니다. 예약 실행을 점검 전용으로 제한하는 것은 에이전트 지시이며 도구 사용을 기계적으로 차단하지는 않습니다.

## 자주 묻는 질문

### Hermes Agent가 같은 실수를 반복하면 어떻게 하나요?

반복 수정 요청과 이미 잘된 반례가 담긴 비교 가능한 대화를 고르세요. Hermes Fit 스킬은 근거를 검토하고 최대 세 개의 작은 지침 변경을 제안하도록 돕습니다. 먼저 도구 오류, 부족한 문맥, 모델 한계가 원인인지 확인합니다. 새 규칙을 추가하는 것이 항상 해답은 아닙니다.

### Hermes 기본 메모리·자가개선과 무엇이 다른가요?

기존 메모리와 스킬 도구를 대체하지 않고 활용합니다. 차이는 근거 확인, 좁은 범위의 제안, 별도 검수, 특정 수정안에 연결된 피드백 절차에 있습니다. 모델 가중치를 학습하거나 모든 대화를 영구 선호로 바꾸지 않습니다. 기본 자가개선과의 전면 비교 연구는 수행하지 않았습니다.

### 지침을 자동으로 고치거나 백그라운드에서 실행하나요?

아닙니다. 오프라인 보조 도구는 공식 도구 호출을 준비하고 상태를 확인합니다. USER 메모리나 스킬 대상을 직접 쓰지 않으며, 실제 변경은 Hermes 공식 도구와 승인 절차를 거칩니다. 반복 점검은 별도 동의가 필요합니다. 지시문과 호출자가 제공한 결과는 보안 격리나 승인자 신원 인증을 대신하지 않습니다.

### 내 대화는 어디로 전달되나요?

오프라인 도구 자체는 네트워크를 호출하지 않지만, 에이전트가 분석하는 선택 대화는 사용 중인 모델 제공자에게 전달됩니다. 자동 가림은 모든 비밀을 찾지 못하고 이미 전달된 내용을 되돌리지 못합니다. 승인한 최소 근거만 고르고 공개 이슈에 개인 대화 파일을 올리지 마세요. [보안 안내](SECURITY.md)를 참고하세요.

### 좋다는 피드백을 주면 다음 변경도 자동 적용되나요?

아닙니다. 피드백은 선택 사항이며 정확한 제안·수정 버전에 연결합니다. 답이 없으면 만족 여부는 알 수 없습니다. 추가 수정에는 근거, 별도 승인과 재검수가 필요하며 한 문제의 수정은 기본 두 차례까지입니다. 만족도와 시험 결과는 서로 다른 지표입니다.

### 실제로 반복 실수가 줄어든다는 효과가 입증됐나요?

아직 아닙니다. 시험은 보조 도구의 동작과 통합 경계를 확인한 것이며 사용자 효과를 입증하지 않습니다. 아래의 날짜·검증 근거와 [베타 한계](https://github.com/junghwoan/hermes-fit/releases/tag/v0.1.0-beta.1)를 참고하세요. 재현 가능한 문제나 좋아짐·비슷함·나빠짐 피드백은 개인정보를 뺀 뒤 [피드백 창구](https://github.com/junghwoan/hermes-fit/issues/1)에 남길 수 있습니다.

공개된 **0.1.0-beta.1 ZIP**의 SHA-256은 `c6376b86be67e934654c6300050d4ea39a5d63146b7d9eb8658879e85b0de18b`입니다. 배포 첨부파일의 식별값이며 이후 `main` 변경본의 해시를 뜻하지 않습니다. 공개 배포물을 실제로 다운로드해 독립 빌드와 일치하는지 확인했습니다. 해당 ZIP을 푼 macOS Python 3.14.7에서 시험 90개·데모·격리 CLI가 통과했고, Linux Python 3.12.3에서도 시험 90개가 통과했습니다. 시험과 데모는 합성 데이터와 모의 평가를 사용합니다.

일회용 홈에서 배포물과 설치된 Hermes v0.22.2 공식 함수 API도 연결해 확인했습니다. USER 메모리 추가와 역변경, 스킬 생성·수정·정확한 역변경·삭제, 일시 정지된 일정 생성부터 목록·전체 프롬프트 확인·등록·제거·부재 확인·보조 파일 정리까지 실행했습니다. 모니터가 작동 중일 때 설치 제거가 거부되는지와 새 읽기 전용 감사가 파일을 바꾸지 않는지도 확인했습니다. 처음 없던 USER 파일은 역변경 뒤 빈 파일로 남을 수 있으며, 이때는 정확한 복구가 아니라 충돌로 표시합니다. 이는 직접 함수 호출 시험으로, 실제 채팅·스케줄러·모델 실행은 확인하지 않았습니다. 작은 합성 사례의 독립 비교에서도 행동 개선 우위는 입증하지 못했으며 실제 사용자 효과 연구는 수행하지 않았습니다. 구조 시험만으로 반복 수정이 줄었다고 판단할 수는 없습니다.
