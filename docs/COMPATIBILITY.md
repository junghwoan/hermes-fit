# Compatibility

The offline helper targets Python 3.10+ on POSIX (Linux and macOS). The parent verified commit `49ba0a8` on macOS Python 3.14.7: all 90 tests, demo and isolated CLI passed. Its independently built 31-file ZIP (SHA-256 `c24684cb47b139274786bc225c6598a796210338f60e66a46d93691d0dce6636`) matched the Linux build; the unpacked ZIP also passed all 90 tests and the demo on macOS. This documentation-only successor has the same runtime and tests but a different archive hash. Windows is not supported; no cloud CI run was performed.

The native plans target v0.22.2. In disposable homes, the parent exercised the candidate installed from that ZIP through actual native function APIs: USER add/inverse; skill create/patch/exact inverse/delete; and paused cron create/list/full prompt readback via `cron.jobs.get_job`, registration, removal, list absence and helper cleanup. Active-monitor uninstall refusal and a fresh read-only audit with no filesystem changes were also verified. If USER memory was initially absent, the native inverse may leave an empty file, so the helper reports a conflict rather than exact rollback. This function-level test did not exercise chat dispatch, scheduler or model execution, or establish user benefit. Caller-supplied tool results are not authenticated.

The helper requires a caller-confirmed version and active timezone. v0.22.2 `parse_schedule` has no per-job timezone or `CRON_TZ` support: wall-clock schedules are accepted only when requested and confirmed active timezones match. Intervals use elapsed time and normalize to `every <minutes>m`. The tool list JSON uses `job_id` and only the first 100 prompt characters plus an ellipsis; there is no `get` action and the CLI list has no JSON flag. A full native prompt comparison requires a separately obtained read-only `cron.jobs.get_job` record. `hermes sessions export` exists in inspected source, but this helper does not import its format.
