# Build stages and acceptance

1. Prepare explicitly selected normalized evidence, split by session, show context and uncertainty.
2. Stage bounded skill or user-memory proposals, including new skills and evidence-gated global scope. Reuse native tools and their own approval gates; observe the target and offer a digest-checked inverse plan.
3. Independently compare held-out cases and frozen guardrails. Distinguish structural validation, recorded judgments and observed recurrence.
4. Record optional feedback and a bounded, separately approved revision with a parent link.
5. Prepare opt-in paused local recurring audit, deploy a bounded monitor and compare native create/list results; only the native tool creates jobs.
6. Export reproducibly and test clean installation. Never package private histories or runtime state.

Native tool responses are caller-supplied observations; independent review, native integration of the entire successor, scheduler dispatch and user efficacy need further verification. A local test pass is not a public release approval.
